# Day 59 – Helm: Kubernetes Package Manager

## Objective
Helm is the **package manager for Kubernetes**. Instead of manually creating multiple YAML files (Deployment, Service, ConfigMap, Secret, PVC, etc.), Helm packages everything into a **Chart** and deploys it with a single command.

**By the end of this day you will learn:**
- Install Helm
- Deploy applications using Helm Charts
- Customize deployments using values
- Upgrade and rollback releases
- Create your own Helm Chart

---

# Task 1: Install Helm

## Install Helm

Choose the installation method based on your operating system.

### Windows (Chocolatey)

```powershell
choco install kubernetes-helm
```

### macOS (Homebrew)

```bash
brew install helm
```

### Linux

```bash
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
```

---

## Verify Installation

Check Helm version:

```bash
helm version
```

View Helm environment variables:

```bash
helm env
```

### Core Helm Concepts

### Chart
A **Chart** is a package containing Kubernetes templates.

Example:
```
Deployment
Service
ConfigMap
Secret
PVC
```

All of these are bundled together.

---

### Release

A **Release** is a deployed instance of a Chart.

Example:

```bash
helm install my-nginx bitnami/nginx
```

- Chart → bitnami/nginx
- Release → my-nginx

You can install the same chart multiple times with different release names.

---

### Repository

A **Repository** stores Helm Charts.

Think of it like:

- apt → Ubuntu packages
- npm → Node packages
- Docker Hub → Docker Images
- Helm Repo → Kubernetes Charts

---

## Verify

```bash
helm version
```

Check the installed Helm version.

# Task 4: Customize with Values

Every Helm chart contains default configuration stored in **values.yaml**.

View it:

```bash
helm show values bitnami/nginx
```

---

## Override Values

Without editing files:

```bash
helm install custom-nginx bitnami/nginx \
--set replicaCount=3 \
--set service.type=NodePort
```

This overrides only the specified values.

---

## Create custom-values.yaml

Example:

```yaml
replicaCount: 3

service:
  type: NodePort

resources:
  limits:
    cpu: 250m
    memory: 256Mi
```

---

## Install Using Values File

```bash
helm install nginx-values bitnami/nginx \
-f custom-values.yaml
```

Helm reads configuration from the file.

---

## View Applied Values

```bash
helm get values nginx-values
```

Shows the overridden values used during installation.

---

## Verify

Check:

```bash
kubectl get deployment
kubectl get svc
```

Confirm:

- Replica count = 3
- Service type = NodePort

# Task 5: Upgrade and Rollback

## Upgrade Release

Increase replicas:

```bash
helm upgrade my-nginx bitnami/nginx \
--set replicaCount=5
```

Helm updates only the changed resources.

---

## View Revision History

```bash
helm history my-nginx
```

Example:

```
REVISION
1
2
```

Each upgrade creates a new revision.

---

## Rollback

Rollback to revision 1:

```bash
helm rollback my-nginx 1
```

Helm restores the previous configuration.

---

## Check History Again

```bash
helm history my-nginx
```

Example:

```
1
2
3
```

Revision **3** represents the rollback operation.

> Rollback creates a **new revision** instead of overwriting old ones, preserving deployment history.

---

## Verify

Check the total number of revisions after rollback.

# Task 6: Create Your Own Chart

Generate a new chart:

```bash
helm create my-app
```

Helm scaffolds a complete project.

---

## Important Files

### Chart.yaml

Contains chart metadata.

Example:

- Name
- Version
- Description

---

### values.yaml

Stores default configuration.

Examples:

- Replica count
- Image
- Service type

---

### templates/

Contains Kubernetes templates.

Example:

```
deployment.yaml
service.yaml
ingress.yaml
```

These use Go template syntax.

Examples:

```yaml
{{ .Values.replicaCount }}

{{ .Chart.Name }}
```

Helm replaces these placeholders during installation.

---

## Edit values.yaml

Update:

```yaml
replicaCount: 3

image:
  repository: nginx
  tag: "1.25"
```

---

## Validate Chart

```bash
helm lint my-app
```

Checks for syntax or template errors.

---

## Preview Generated YAML

```bash
helm template my-release ./my-app
```

Renders the manifests without installing them.

Useful for debugging templates.

---

## Install Chart

```bash
helm install my-release ./my-app
```

Creates Kubernetes resources from your chart.

---

## Upgrade Chart

```bash
helm upgrade my-release ./my-app \
--set replicaCount=5
```

Updates the deployment to 5 replicas.

---

## Verify

Check:

```bash
kubectl get deployment
```

Confirm:

- Initial replicas = 3
- After upgrade = 5

---

# Task 7: Clean Up

Remove Helm releases:

```bash
helm uninstall my-nginx

helm uninstall custom-nginx

helm uninstall nginx-values

helm uninstall my-release
```

---

## Keep Release History (Optional)

```bash
helm uninstall my-nginx --keep-history
```

Useful for auditing or future recovery.

---

## Remove Local Files

Delete:

- my-app/
- custom-values.yaml

---

## Verify Cleanup

```bash
helm list
```

Expected output:

```
No releases found.
```

# Key Takeaways

- Helm is the package manager for Kubernetes.
- A **Chart** packages Kubernetes resources into reusable templates.
- A **Release** is a deployed instance of a Chart.
- A **Repository** stores Helm Charts for easy installation.
- `values.yaml` allows customization without editing templates.
- `helm upgrade` updates deployments while preserving history.
- `helm rollback` restores previous versions by creating a new revision.
- `helm create` scaffolds a complete chart structure.
- `helm lint` validates charts, and `helm template` previews generated manifests before deployment.
